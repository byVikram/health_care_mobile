# Consultation vitals

The doctor's vitals card and sheet in the Notes tab of a consultation.

## Vitals card and sheet

**Consultation vitals** (Notes tab of `features/consultation/ConsultationPage.tsx`; design `vitals.html`, variant B: a card that opens a bottom sheet). The first thing in the Notes tab is `components/VitalsNotesCard.tsx`: nothing recorded today shows a dashed "Vitals not recorded" card (last reading, **Record**), otherwise the time, "N need attention" / "All normal", **Edit** and one chip per reading, the most worrying first. Record / Edit open `components/RecordVitalsSheet.tsx` (`AppBottomSheet`, eight `components/VitalFieldTile.tsx`: BP systolic / diastolic, pulse, SpO₂, temperature (°F), random sugar (RBS), weight (kg), height (cm), both taken at every visit; the dot and border of a tile follow how the typed value rates). **Normal / medium / high is decided by the backend** (`patients/vitals.py`, one table; `docs/patient-vitals.md` there): every record it returns has a `rating` (`normal`, `medium`, `high`; a clearly low reading is `high` too; null for weight, height and others), shown as colour only (green, amber, red), and while a value is typed `GET /api/patients/vitals/ranges` (`getVitalRanges`, fetched the first time the sheet opens) gives the bands `rateTyped` colours the field by; if that request fails the field is simply not coloured. No cut-off lives in the app any more (`VITAL_THRESHOLDS`, `CLEARLY_OUT` and `rateVital` are gone). The card's chips and the Overview cards take the `rating` of the saved record (`todaysVitals` returns it per field, `ratingOf` / `worstRating`); a pulse saved the old way inside an `others` record is rated by the backend as that record's rating, so its chip is coloured too. Today's card is built from the readings of the last 2 days (`GET /api/patients/{id}/vitals?days=2` through `getRecentVitals`, the page's `recentVitals`: each field takes its newest value of the CLINIC day, IST, so a later "others" record without a pulse cannot hide it; the empty card's "Last on 12 Jun" line still comes from `GET .../vitals/latest`) and saved through `recordVitals` in `VitalsService.ts`, one `POST /api/patients/vitals` per vital type with a shared `recorded_at` (`blood_pressure` {systolic, diastolic}, `pulse` {pulse_rate}, `spo2` {spo2}, `temperature` {temperature}, `glucose_level` {random}, `weight` {weight}, `height` {height}: the contract of the backend's `docs/patient-vitals.md`, the same the web app sends; the backend refuses a value outside its range with a 400 that says why, and a pulse saved the old way, in an `others` record, is still read); a save returns the records it created and the page puts them into `recentVitals` and `latestVitals` at once (no second request to wait for), so the card and the Overview cards show them immediately. Only new or changed readings are sent (`buildVitalEntries`), so an edit or a retry after a partial failure never repeats a saved one. The logic (fields, ranges, validation, entries, today's summary) is in `vitalsEntry.ts` and the state / save in `useRecordVitals.ts`; A typed value is refused outside a plausible range (`PLAUSIBLE`: SpO₂ 50-100, temperature 90-110 °F with a hint when it looks like °C, systolic above diastolic). The draft lives in `RecordVitalsSheet` (a keystroke does not re-render the page; fields not yet touched follow today's readings if they arrive late). Until today's readings are fetched the card says so and `openSheet` waits (`RecentLoad`: a failed fetch shows Retry), so a doctor is never offered an empty sheet for readings already taken. `recordVital` skips the global error dialog; a failed save names the server's reason. The Overview pulse is the most recent of the `pulse` record and, for older readings, `blood_pressure.pulse` and `others.pulse_rate` (`latestPulse`). The header's weight and BMI use today's weight and height readings, else the profile's (`bodyMetrics`); `getLatestVitals` takes the BMI's height from the latest `height` reading. With the notes already submitted the card is read-only. Not run on a device yet: `npx tsc --noEmit` only.
